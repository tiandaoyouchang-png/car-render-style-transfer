# 3.0.9 白模构图一致性审视

结论：先确保白模与控制图使用同一个相机画布，消除后处理和重试过程中的偏移，再验证生成模型的服从程度。单纯继续加长提示词不能修正插件自身的坐标错误。

## 代码审查发现与处理

| 原流程问题 | 3.0.9 处理 | 剩余边界 |
| --- | --- | --- |
| 捕获可能受场景局部边框 / 裁切设置影响 | 捕获时关闭并恢复这些设置；检查实际 PNG 尺寸 | 需在不同 Blender 版本 GUI 验证 |

## 当前验收与纠偏策略

1. 本地确认候选图真实宽高比，容许整数像素舍入。FAST / STANDARD 只记录提示，不增加生图或视觉审计调用。
2. STRICT 比例不对时，本地判失败，跳过远程视觉评分，并在剩余次数内从白模重试。
3. 比例通过后，由选定 Provider 观察候选主体边界。中心偏移超过画幅 1.5%、宽 / 高相对目标偏差超过 4%，或包围框 IoU 低于 0.9，会限制评分并形成量化纠偏。这些为启发式阈值，尚未按用户样本校准。
4. 只有边界可信度至少 0.7、视角分达到用户通过阈值、联合区域小于画幅 80% 时尝试局部修复，否则从白模重建。具体轨迹和估计数值保存在 Session 元数据。
5. 有效画布优先于不兼容画布；同类画布按评分保留最佳候选。远程验收异常时保留已有结果，不盲目消耗剩余尝试次数。

## 能做到什么、不能保证什么

从本工程请求代码可见，Codex / AGY 接收的是白模、结构图和编辑要求。新增逻辑要求可用的图像工具选择高保真、匹配尺寸，并在有 Mask 参数时使用 Mask；插件不能验证后端是否真的暴露或执行了这些参数。

专用 ControlNet 在模型内部接收边缘 / 深度等条件，还可以设置控制权重；这与将几张控制图作为一般参考附件不同。[Hugging Face 官方 ControlNet 文档](https://huggingface.co/docs/diffusers/using-diffusers/controlnet)

据此判断：当前版本可以消除若干确定性的输入 / 后处理错误，并改善验收与修复策略，但不能承诺生成图与白模逐像素一致。若业务要求几何绝对准确，最终几何应继续由 Blender 渲染保证；更强的生成控制需后端真正支持深度 / 边缘条件并另行验证，本版没有替换用户选择的 Provider 或加入新后端。

## 如何验证真实改善

固定一个相机、产品集合、文字和两类参考，覆盖近景 / 中景、横 / 竖画幅及明显环境光差异。记录白模、原始候选、控制图、Session 元数据以及耗时；用轮廓与叠加检查边界、轮心、朝向、地平线。比较多次重复结果的偏移和通过率，避免只挑一张成功图。当前只完成离线逻辑验证，尚无真实图片对照统计。
